- `docker run -d --name mypg -e ...`로 postgres 컨테이너를 띄우고 `docker ps`로 확인
- `docker exec -it mypg psql -U postgres`로 접속하면 프롬프트가 `postgres=#`로 바뀜
    - `-i`는 interaction, `-t`는 tty
    - 별도 유저를 만들면 프롬프트에 해당 유저명이 표시됨

### psql 기본 명령

- `\l`은 DB 목록 조회. 기본 DB는 시스템/템플릿용이라 직접 쓰지 않음
- 데이터베이스는 테이블을 모아두는 그룹 역할
- `CREATE DATABASE cantshop;`으로 생성. DB·테이블명은 소문자가 관례
- 이런 문장은 DML이라 소개했으나 정확히는 DDL(데이터 정의어)이며, 문장 끝에 세미콜론이 필수
- `DROP DATABASE`로 삭제. 없는 DB를 지우면 에러 발생
- 긴 출력에서 `END`가 표시되면 `q`로 빠져나옴
- 실무에서는 터미널에서 직접 테이블을 만들지 않고, SQL 파일을 작성해 컨테이너로 밀어 넣는(import) 방식을 많이 씀

### VS Code 설정

- 터미널 최대화/복원 단축키 설정을 권장

### cantshop.sql 작성 내용

- 주석은 `--`. 파일은 DB 안에서 실행되는 SQL임
- RDB 이론(PK, FK, 인덱스)은 아직 설명하지 않았고 지금은 "이런 게 있구나" 수준으로만 기억
- 구성 순서
    - `CREATE DATABASE cantshop;`
    - `\c cantshop`으로 해당 DB에 접속 (SQL 문법이 아니라 세미콜론 불필요)
    - `CREATE TABLE product` (실무에서는 ERD로 설계 후 DDL 추출)
    - 상품 초기 데이터 INSERT
- product 테이블 컬럼
    - `id`: SERIAL PRIMARY KEY (자동 증가, MySQL의 AutoIncrement와 동일)
    - `name`: VARCHAR(100) NOT NULL (가변 길이, 남는 공간은 최적화)
    - `price`: INT NOT NULL (금융/화폐는 DECIMAL 사용 권장)
    - `stock`: INT NOT NULL
- 문법 스타일은 중괄호 줄바꿈을 선호해 블록 위치를 명확히 함
- INSERT 구문은 `INSERT INTO 테이블(컬럼) VALUES (...)` 형태로 기억. 문자열은 작은따옴표, 마지막에 세미콜론. 예: 무선 이어폰, 35,000원, 재고 100
- 반복 테스트를 위해 `DROP DATABASE IF EXISTS cantshop;`를 맨 앞에 추가 (문법은 테스트 후 확인 예정)
- 저장하지 않으면 탭에 동그라미가 표시되므로 반드시 Ctrl+S

# 1-2. AI 요약│Docker Postgres SQL 파일 실행 실습
### Action Items

- [ ]  Windows 사용자: bash 셸 설정 파일(.bashrc)에 export 설정을 추가한 뒤 `source`로 갱신해 적용하기. 인식이 안 되는 수강생은 테스트 후 다시 진행
- [ ]  수강생: `docker-cmd.md` 마크다운 파일에 실습 명령어를 정리해 TIL 작성에 활용하기
- [ ]  SQL 파일 수정 후에는 컨테이너로 다시 복사(`docker cp`)한 뒤 재실행하기

### 실습 흐름 개요

- psql CLI로 접속해 `\l`로 데이터베이스 목록을 확인하고 `\q` 또는 `exit`로 빠져나옴
- SQL 파일을 실행하는 방법은 두 가지: (1) 컨테이너 내부로 복사 후 실행, (2) 외부에서 직접 덤핑. 이번에는 첫 번째 방법을 먼저 진행

### 마크다운 명령어 정리

- 명령어가 길어 `docker-cmd.md` 파일을 만들고 명령어를 마크다운으로 기록. TIL 작성에도 도움이 됨
- 코드 블록은 백틱으로 감싸고 언어를 `sh`로 지정하면 색깔이 적용됨
- `docker ps`는 컨테이너 목록 조회, `docker ps -a`는 정지된 컨테이너까지 조회

### SQL 파일을 컨테이너로 복사

- `cp`는 copy의 의미이며 문법은 `대상 파일 → 목적지` 순서
- 형식은 `docker cp <파일> mypg:/tmp/<파일>`. `mypg`는 컨테이너 이름이고 콜론을 빼먹으면 안 되며, 컨테이너 안은 절대경로를 사용
- Postgres 컨테이너는 가벼운 리눅스 기반이라 `/tmp` 폴더가 있어 간단히 사용 가능
- "Successfully copied" 메시지가 나오면 성공
- 도커 데스크톱의 Files 탭에서 `tmp` 폴더 안의 파일을 확인, 다운로드, 열람, 수정할 수 있음 (당장은 수정 사용 비권장)

### 컨테이너 내부에서 SQL 파일 실행

- 명령어: `docker exec -it mypg psql -U postgres -f /tmp/<파일>.sql`. `-f`는 file의 약자
- 실행 시 16번 라인에서 syntax error가 발생. 원본 SQL 파일을 수정 후 다시 복사해 재실행
- 재실행 결과: drop database → create database → 데이터베이스 연결 → create table → insert 0 5(5개 행 추가) 순으로 출력됨
- 일부 Windows 수강생은 경로가 달라 문제가 생겼고, 슬래시를 하나 더 붙여(`//`) 시도하도록 안내함. Mac과 동작이 다른 이유를 확인 중
- Postgres의 철자 오류(`postgres`에 r 하나 부족) 사례도 확인

### 주석 작성 시 주의점 (SQL 파일)

- 파이썬은 `#`으로 주석을 달지만 SQL은 `--`(대시 2개)로 주석을 달아야 함. 노트에는 도커로 적혀 있으나 SQL 파일 맥락임
- 이 차이 때문에 명령어 실행 오류가 날 수 있음
- `drop database if exists`로 이미 있는 데이터베이스는 삭제 후 생성

### Windows 환경 설정 (Bash)

- Windows와 Mac 설정이 달라 Windows 사용자만 별도 진행
- Git Bash의 `.bashrc`(홈 디렉터리의 숨김 파일)에 export를 추가하고 `source`로 갱신하면 전역으로 사용 가능
- 일부 수강생은 export가 인식되지 않아 나중에 다시 진행. 급하지 않아 테스트 후 다시 공유 예정
- 복사 시 따옴표가 작은따옴표 등으로 바뀌어 문제가 될 수 있음

### 데이터베이스를 지정해 접속

- 지금까지는 기본 접속이었고, 이제 DB를 지정해 접속하는 방법을 실습
- 명령어: `docker exec -it mypg psql -U postgres -d <DB명>`. `-d`는 데이터베이스 이름 옵션
- 접속하면 프롬프트에 DB명이 표시됨
- 테이블 목록은 `\dt`로 확인하고 `product` 테이블이 보이는지 점검

### 기본 조회 (SELECT)

- `SELECT * FROM product;`로 조회. `*`는 모든 컬럼을 의미하며 컬럼은 총 4개
- 가장 기본 형식은 `SELECT * FROM 테이블명;`

# 1-3. AI 요약│Docker와 Postgres 볼륨 실습 및 Compose 소개

### 컨테이너 강제 삭제 및 재생성

- 기존 컨테이너를 정지하지 않고 `docker rm -f`(f는 force)로 강제 삭제
- 컨테이너를 통째로 삭제했으므로 앞서 만든 데이터베이스와 테이블이 모두 사라짐
- 실행 명령: `docker run -d --name my-pg -e POSTGRES_PASSWORD=admin1234 -p 5432:5432 postgres:18`
- 로컬 파일을 `docker cp` 없이 redirection으로 컨테이너에 바로 넣는 방식을 실습

### 컨테이너 접속 방법

- 첫 번째는 컨테이너에 직접 들어가는 방법, 두 번째는 `docker exec ... psql`로 접속하는 방법으로, 두 번째를 가장 많이 쓰게 됨
- 터미널 환경이 아니므로 `-it`가 아닌 `-i`만 써야 함 (`-it`는 "cannot attach" 오류 발생)
- 이 방식으로 `drop database` / `create database`를 실행
- 데이터베이스 지정(`-d`)은 스크립트 안에서 connection 하므로 생략 가능
- 컨테이너를 "올린다(up)"는 표현은 실행·로드의 의미로 쓰임
- 긴 명령은 역슬래시(`\`)로 줄바꿈할 수 있으나, 터미널에 익숙해진 뒤에 쓰기를 권장

### SQL 조회 기초

- `\l`로 데이터베이스 목록, `\d`로 현재 DB의 테이블 목록 확인
- `SELECT name, price FROM product;`처럼 SELECT와 FROM 사이에 컬럼명을 쓰면 원하는 컬럼만 조회됨
- `\q`로 종료

### 볼륨(Volume)

- **필요성**: 컨테이너를 삭제하면 데이터도 사라지므로, 호스트 OS에 물리 파일로 데이터를 저장하는 볼륨을 사용. 앞으로 작업 시 필수
- **생성 방법 2가지**: 직접 볼륨을 생성해 컨테이너와 연결하는 방법(오늘 실습)과, 컨테이너 생성 시 자동 볼륨으로 세팅하는 방법
- 주요 명령어
    - `docker volume ls`: 목록 조회. 일부 수강생에게 기존 볼륨이 보임
    - `docker volume create pg-data`: 볼륨 생성
    - `docker volume inspect`: 생성일, 마운트 포인트 등 상세 정보를 JSON으로 확인
- 팁: VS Code에서 Ctrl+Shift+V로 마크다운 미리보기를 켜고 끌 수 있음

### 볼륨 연결 실행

- `-v pg-data:<컨테이너 내부 경로>` 형식으로 볼륨을 연결
- **중요**: Postgres 17 이하와 18 이상은 마운트 경로가 다름. Docker Hub 이미지 상세 페이지에서 확인해야 하며, 현재는 18 버전 경로를 사용
- 오타 주의: 이미지명은 `postgres`이며 `s`가 하나
- 기존 컨테이너에는 볼륨을 연결할 수 없어 `docker rm -f`로 삭제 후 처음 생성 시 연결해야 했음
- 검증 순서
    1. `docker exec -it ... psql -U postgres -d <DB> -c "select * from ..."`로 데이터 입력 후 5개 항목 확인 
    2. 컨테이너 강제 삭제 후 `docker volume ls`로 pg-data가 남아있음을 확인 
    3. 같은 볼륨으로 컨테이너를 다시 생성해 조회하면 데이터가 그대로 남아있음 
- `-c` 옵션은 command의 약자로, 컨테이너에 들어가지 않고 터미널에서 바로 쿼리 실행 가능

### Docker Compose 소개

- 복잡한 docker 명령 옵션을 매번 입력하기 어려워 `docker compose up` 한 줄로 처리
- 서비스 개발에는 Postgres, FastAPI, Node.js 등 여러 컨테이너가 필요하며, 하나의 파일로 쉽게 올리고 내릴 수 있음
- 볼륨 설정도 설정 파일로 간단히 관리 가능
- 다음 주제로 예정

### compose.yaml 작성 방법

- 확장자는 YAML(야믈)이며 JSON과 비슷한 설정 파일 형식으로, 초기 환경 설정과 컨피그 파일에 많이 쓰임
- 파일명은 `compose.yaml`로 정확히 써야 함
- 들여쓰기가 매우 중요함. 스페이스 두 칸을 쓰고 탭은 쓰지 않음. VS Code에서는 탭이 자동으로 두 칸 들여쓰기가 됨
- 서비스 이름은 자유롭게 정할 수 있으며 `db`로 지정
- 주요 항목
    - image: 로컬에 받아둔 `postgres:18` 이미지 (태그는 버전 번호)
    - container_name: 기존 `mypg`와 겹치지 않도록 `kant-pg`로 지정
    - environment: key-value 형식으로 `POSTGRES_PASSWORD`를 입력하고 값은 `admin1234`. 콜론 뒤에 한 칸을 띄워야 함
    - ports: 쌍따옴표로 감싸며 `"5432:5432"` 형식(호스트 포트:컨테이너 포트). `-p` 옵션에 해당
    - volumes: 기존에 만든 볼륨 `pg-data`를 컨테이너 내부 경로에 마운트. `-v` 옵션에 해당
    - external: 직접 만든 볼륨을 쓸 때는 `external: true`를 지정해야 함
- `docker compose` 명령은 `compose.yaml`이 있는 폴더에서 실행해야 함

### 검증 및 환경 설치 이슈

- `docker compose config`로 문법과 들여쓰기 오류를 확인하며, 정상이면 설정이 출력됨
- 일부 수강생은 `docker compose config`가 동작하지 않았음
    - 서비스 항목에서 'c'가 빠진 오타 사례가 있었음
    - 필요한 3개 패키지 설치 여부를 확인하도록 안내함
    - 맥 사용자는 별도 명령어로 설치한 뒤 버전을 확인함

### 실행과 종료

- `docker compose up -d`: 서비스를 백그라운드로 생성하고 실행. 긴 `docker run` 옵션이 필요 없음
- 포트 충돌
    - 기존 `mypg`가 5432 포트를 쓰고 있어 "port already allocated" 오류 발생
    - 외부 포트를 5433으로 바꾸고 저장한 뒤 다시 `up` 실행
    - 외부 포트만 다르면 되고 내부 포트는 상관없음. 컨테이너가 격리되어 두 개가 동시에 실행됨
    - `docker ps`로 5433(kant-pg)과 5432(mypg) 두 컨테이너 확인
- `docker compose down`: 컨테이너만 내림. `-v` 옵션을 쓰면 볼륨까지 삭제되므로 쓰지 않음
- 예상 밖 현상
    - 컨테이너를 내렸는데 `mypg`가 삭제되지 않고 중지 상태로 남거나 사라지는 등 예상과 다르게 동작함
    - 이후 `docker rm`으로 `mypg`를 삭제함
    - 강사는 "라이브 강의에서는 시나리오대로 해야 한다"고 언급함

### Compose의 장점과 데이터 유지 확인

- 환경변수, 비밀번호, 포트 등을 파일 하나에 기술해 두면 재사용할 수 있음
- nginx 같은 서비스를 추가하면 한 번에 함께 올릴 수 있음
- 컨테이너 이름이 바뀌고 compose로 올렸어도 같은 볼륨을 쓰므로 기존 데이터가 그대로 조회됨
- `docker compose ps`는 compose로 띄운 컨테이너만 보여주므로 여러 서비스 관리에 유용

### DB Code 확장으로 DB 조회

- VS Code 확장 'DB Code'를 설치하고 연결을 추가함
- 연결 설정
    - PostgreSQL 선택
    - 연결 이름: `kant-shop`
    - 호스트: localhost, 포트: 5433
    - 사용자: `postgres` (스펠링 주의), 비밀번호: `admin1234`
- 새로고침 후 `kantshop` DB와 public 스키마의 `product` 테이블(컬럼 4개, 기본키 1개)을 확인함
- 이 도구는 간단한 조회 용도로만 사용함
    - 데이터가 많거나 쿼리 결과가 크면 감당하기 어려움
    - DB는 코드와 달리 복구가 어려워 안정적인 도구를 써야 함
    - DB 관리에는 DataGrip을 사용할 예정이며, 다음 주부터 주력으로 쓰지는 않지만 사용해 볼 계획
